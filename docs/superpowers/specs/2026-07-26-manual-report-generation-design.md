# 手动生成报告设计

## 目标

录音、上传音频和粘贴文本完成后只展示最终转写；用户点击“生成报告”后才调用反馈模型、保存历史并打开报告。

## 交互

- 录音按钮在录音中显示“结束录音”，停止后状态显示“转写已完成”。
- 上传音频识别结束后状态显示“转写已完成”。
- 粘贴文本提交后直接展示原文，不生成报告。
- 有待处理内容时显示独立“生成报告”按钮。
- 生成期间按钮禁用，状态显示“正在生成报告”。
- 成功后隐藏按钮、保存历史并打开报告。
- 开始新的录音、上传或文本任务时丢弃尚未生成的待处理报告。

## 逻辑边界

- `PracticeOrchestrator.finish()` 只停止 ASR、冲刷末句并确定真实时长。
- `PracticeOrchestrator.generateReport()` 只基于已完成会话生成报告。
- Electron 主进程保存一个待生成报告上下文，记录来源、转写、时长和文件名。
- 新增统一的 `practice:generate-report` IPC；渲染进程不直接持有模型或报告生成器。
- 历史记录只在报告成功生成后写入。
- 报告失败时保留待处理上下文，允许再次点击重试。

## 兼容范围

- 保留现有 AudioWorklet、Sherpa-ONNX、上传重采样、转写清洗和真实时长计算。
- 保留旧的报告展示、Markdown 导出和历史读取。
- 不增加依赖，不修改 ASR 模型。

## 验证

- 测试停止录音不调用报告模型。
- 测试点击生成后才产生报告并保存历史。
- 测试上传音频和粘贴文本遵循相同手动流程。
- 测试报告失败后可重试。
- 测试新任务会清除旧的待处理上下文。
- 运行完整测试与真实 ASR 验证。
