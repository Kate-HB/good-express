# 深度表达报告与真实音频时长设计

## 目标

以 `expression-trainer` 报告为深度基准，增强 Good Express 的逐句编辑、行为模式、直接性和结构分析；上传音频一律按采样数计算真实时长。ASR 链路保持不变。

## 报告结构

- 总评：总分、整体定位、最核心问题。
- 亮点：引用原句并说明具体价值。
- 逐句编辑：原文、建议、原因、分析维度。
- 用词精准度：原词、候选替换、适用说明。
- 行为模式：填充词、犹豫表达、直接性及引用证据。
- 说服力与结构：钩子、核心观点、例子、收尾行动。
- 数据：真实时长、字数、语速、填充词和模糊词。
- 下次练习：只给一个重点及可执行步骤。

现有 `summary`、`highlights`、`weaknesses`、`rewrites`、`vocabulary`、`metrics`、`exercise` 字段继续保留，新增 `score`、`positioning`、`behaviorPatterns`、`structureAnalysis`，避免破坏历史记录和本地降级报告。

## 分析边界

- 不把明显 ASR 乱码直接判定为口误、人格或心理问题。
- 心理和行为判断必须引用原文；证据不足时使用“转写中表现为”，不得做人格诊断。
- 不编造人物姓名、事件、数字和时长。
- LLM 失败时继续返回现有本地规则报告。

## 时长数据流

- 实时录音：继续使用录音开始到停止的实际时间。
- 上传音频：使用 `原始采样数 / 原始采样率`；分块识别耗时不得参与语速计算。
- IPC 分块上传累计 16 kHz PCM 样本数，停止时传入 `累计样本数 / 16000`。
- `PracticeOrchestrator.stop()` 接受可选 `durationSeconds` 覆盖值；未传时使用墙钟时长。

## 展示与导出

界面和 Markdown 均展示新增深度章节；旧历史记录缺少新增字段时安全显示现有章节。完整原文继续保留。

## 验证

- 测试上传音频的报告时长和语速基于样本时长。
- 测试 LLM 提示词包含完整报告结构、证据约束和 ASR 边界。
- 测试新增字段合并、LLM 失败降级、旧报告兼容。
- 测试 Markdown 与界面包含行为模式和结构分析。
- 运行完整测试与真实 ASR 验证。
