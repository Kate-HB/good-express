# 算法说明

## 1. 为什么 DLUT 不能直接替词

DLUT 记录词语的情感类别、强度和极性。例如它能帮助区分积极、消极和不同强度，但“情绪接近”不等于“语义可互换”。因此系统把它作为分析特征，不把同一情感类别的词全部当成同义词。

## 2. 候选召回

`precision-map.json` 与 `precision-additions.json` 保存 30 个高频模糊表达。候选统一为 `tone/intensity/formality/purposes/positiveExample/negativeExample/reason` 结构。召回只回答“有哪些词可能合适”，此时还不决定最终顺序。

## 3. 语境排序

规则排序读取当前句、最近上下文和推断目的。计划类线索“先、再、步骤”提升“打算”；未来目标线索“考上、成为”提升“希望”；强烈长期诉求提升“渴望”。排序后只保留前三项，并生成替换后的完整句子。

若配置 LLM，它先重排本地候选，也能补充本地词表外的候选。补充项只有同时满足以下条件才会展示：

1. 结构完整且置信度不低于 0.65。
2. 确实替换原句中的目标词，并返回完整改写句。
3. 不与已有候选重复。
4. 原词和候选都能在 DLUT 中查到时，情感极性不能冲突。

1.5 秒内没有结果就使用本地排序，因此断网或模型故障不会阻塞录音。

## 4. 保守 ASR 纠错

系统同时保存 `rawTranscript` 与清理后的 `transcript`。纠错只处理高置信度重复、计划语境中的特定同音错误和句末标点。中文双字先经过 ICU 分词，“爸爸、谢谢、星星”等合法叠词保持不变。每次修改记录原文、替换、规则和置信度，报告可追溯。

## 5. 最终报告

报告只使用转写、统计与已经产生的建议。每条不足必须包含 `quote/evidence/impact/action/revised`；同一证据不重复使用。训练任务只能有一个，让下一次练习有明确重点。
